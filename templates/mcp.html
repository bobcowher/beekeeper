Beekeeper MCP Server

Connect AI agents via the Model Context Protocol

Overview

The Beekeeper MCP server exposes all training management operations as MCP tools. AI agents (Claude Code, Claude Desktop, and any MCP-compatible client) can control training jobs, read logs, analyze metrics, and manage projects — no shell binary required.

analyze_run() provides a Synthesized View — TensorBoard trends and log-based episode metrics combined into a single response, designed for agent consumption without screenshots or manual parsing.

Setup

1. Install the MCP server

pip install beekeeper-mcp

2. Register the MCP server

Claude Code — run this once in your terminal: 

claude mcp add beekeeper -s user -e BEEKEEPER_HOST=http://{{ request.host }} -- beekeeper-mcp

If auth is enabled, also add -e BEEKEEPER_API_KEY=your-api-key before --. Generate an API key from the Admin Panel.
If beekeeper-mcp isn't found (common with conda), use the full path: run which beekeeper-mcp and use that instead.

Claude Desktop — add to ~/.claude/claude_desktop_config.json: 

{
  "mcpServers": {
    "beekeeper": {
      "command": "beekeeper-mcp",
      "env": {
        "BEEKEEPER_HOST": "http://{{ request.host }}",
        "BEEKEEPER_API_KEY": "your-api-key"
      }
    }
  }
}

Omit BEEKEEPER_API_KEY if authentication is disabled.

3. Paste this into your first message

Copy and paste this into Claude to orient it at the start of a session:

You have the Beekeeper MCP server connected. Beekeeper manages ML training jobs on a remote GPU server.

Get oriented:
1. Call list_projects() to see what projects exist
2. Call get_project_instructions("<project-name>") for the one you want to work with and read it fully
3. Call analyze_run("<project-name>") to see the current training state
4. Save key context (project name, primary metric, training goals) to your memory so you have it next session
5. Give me a status report: what's running, how it's performing, anything worth flagging

Replace <project-name> with your actual project name after list_projects() returns.

Tool Reference

Projects

Tool Description
list_projects() All projects with name and status
get_project(name) Detailed project info: git URL, branch, setup status
create_project(name, git_url, ...) Create a project; setup runs in background
retry_setup(name) Retry failed setup, polls until done
delete_project(name) Delete project and all data
get_project_instructions(name) Full project-specific agent context as markdown

Training

Tool Description
start_training(name) Start training (pre-launch: git pull + pip install)
stop_training(name) Stop the active training process
training_status(name) Current training state

Logs & Analysis

Tool Description
get_logs(name, tail=100) Last N lines of training output
analyze_run(name) Synthesized View: TensorBoard trends + episode log metrics in one response. Works even when TensorBoard hasn't flushed yet.

Branches

Tool Description
list_branches(name) All remote branches; shows current branch
switch_branch(name, branch) Switch branch (training must be stopped)

System

Tool Description
get_stats() GPU utilization, VRAM, CPU, RAM
check_busy() Is any training currently running? Always call before starting a new run.

Example Workflows

Check system state

check_busy()
get_stats()
list_projects()

Analyze a training run

analyze_run("my-project")
get_logs("my-project", tail=100)

Start training

check_busy()
training_status("my-project")
start_training("my-project")

Create and start a new project

create_project("my-project", "https://github.com/user/repo.git")
retry_setup("my-project")   # blocks until setup_status == ready
start_training("my-project")
